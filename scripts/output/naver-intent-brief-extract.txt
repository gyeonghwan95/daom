“부산 상속전문 법무사”, “부산 법인전문 법무사”처럼 ‘전문’ 표현이 포함된 키워드는 실제 경력·업무 내용·광고 관련 기준으로 객관적으로 사용할 수 있는지 먼저 검토한다. 입증하기 어렵다면 제목의 주 키워드는 “부산 상속 법무사”, “부산 상속등기 법무사”, “부산 법인등기 법무사”, “법인등기 중심 법무사”처럼 정확한 업무 표현으로 바꾸고, 사용자가 검색할 수 있는 표현은 본문에서 자연스럽게 설명한다.

기존 URL은 절대 삭제하거나 임의로 변경하지 않는다. URL 통합, redirect, canonical 변경, noindex가 필요하다고 판단되더라도 자동 적용하지 말고 별도 승인 목록으로 보고한다.

1. 기존 페이지 전수 진단
━━━━━━━━━━━━━━━━━━━━

먼저 프로젝트의 모든 색인 가능 페이지를 크롤링하여 다음 정보를 표 또는 JSON/CSV로 정리해줘.

- URL
- HTTP 상태
- 색인 가능 여부
- title
- H1
- meta description
- canonical
- 본문 글자 수
- 실제 본문 문단 수
- 카드·목록 비중
- 주 키워드
- 보조 키워드
- 검색 의도
- 상위 허브
- 내부링크 유입 수
- 내부링크 발신 수
- sitemap 포함 여부
- 구조화 데이터
- 대표 이미지와 alt
- 다른 페이지와 제목 유사도
- 다른 페이지와 본문 유사도
- 다른 페이지와 FAQ 유사도
- 마지막 실제 수정일

특히 다음 문제를 찾아라.

- 동일하거나 거의 같은 title
- 동일한 description
- H1과 title이 모든 페이지에서 동일한 패턴
- 지역명이나 업무명만 바뀐 본문
- 첫 문단이 여러 페이지에서 반복
- 핵심 요약 카드만 있고 실제 본문이 부족한 페이지
- “절차·비용·서류 총정리” 제목이 과도하게 반복되는 페이지
- 같은 키워드를 여러 URL이 주 키워드로 사용하는 경우
- 페이지마다 동일한 실제 사례·FAQ·CTA가 반복되는 경우
- 검색 키워드와 본문 내용이 일치하지 않는 경우
- canonical과 sitemap URL이 다른 경우
- 고립 페이지
- 초기 HTML에 본문이 없고 클라이언트 렌더링 후에만 나타나는 페이지

각 페이지를 다음 상태로 분류해줘.

- KEEP: 현재 구조와 내용이 양호하여 유지
- IMPROVE: URL과 검색 의도는 유지하면서 본문·제목·UI 개선
- REPOSITION: 기존 URL을 다른 고유 검색 의도로 재정의
- MERGE-CANDIDATE: 다른 페이지와 검색 의도가 같아 통합 검토
- CREATE: 사이트에 없는 중요한 검색 의도
- TECH-FIX: 콘텐츠보다 canonical·HTML·수집·성능 문제가 우선

기존 페이지를 무조건 다시 쓰지 말고, 실제로 문제가 있는 페이지부터 개선한다.

2. 키워드가 아니라 검색 의도 기준으로 대표 URL 지정
━━━━━━━━━━━━━━━━━━━━

각 핵심 검색어 묶음마다 하나의 대표 URL만 주 페이지로 지정한다.

- 해외 거주 상속인이 있는 경우
- 미성년 상속인이 있는 경우
- 한정승인 이후 채권자 통지·청산 절차
- 상속재산파산 검토가 필요한 경우

- 급여압류 전후 개인회생
- 보증채무가 있는 경우
- 채무가 많지만 소득이 적은 경우

1. 부산 법무사 종합 허브

━━━━━━━━━━━━━━━━━━━━
4. 페이지별 권장 콘텐츠 길이
━━━━━━━━━━━━━━━━━━━━

네이버가 좋아하는 절대적인 글자 수가 있다고 가정하지 않는다. 검색 의도를 충분히 해결할 수 있는 정보량을 기준으로 다음 범위를 내부 목표로 사용한다.

- 종합 허브·대표 페이지: 본문 약 3,000~5,000자
- 핵심 업무 페이지: 약 2,200~3,800자
- 상황별 상세 페이지: 약 1,600~3,000자
- 비교·선택 페이지: 약 1,800~3,200자
- 실제 사례 페이지: 약 1,500~2,800자

메뉴, breadcrumb, 관련 글 제목, 공통 CTA 문구는 본문 글자 수에서 제외한다.

목표 글자 수를 채우기 위해 표현을 반복하지 않는다. 고유한 정보를 1,500자 이상 작성할 수 없는 페이지는 신규 페이지로 만들지 말고 상위 허브의 섹션·사례·FAQ로 흡수한다.

━━━━━━━━━━━━━━━━━━━━
5. 본문 구조
━━━━━━━━━━━━━━━━━━━━

모든 페이지를 동일한 카드형 템플릿으로 복제하지 않는다. 기본적인 읽기 흐름은 유지하되 업무별로 필요한 모듈만 선택한다.

권장 흐름:

1. H1
2. 검색자의 상황을 정확히 짚는 도입 2~4문장
3. 핵심 요약 카드 1개
4. 최소 1,200~1,800자의 자연스러운 줄글 본문
5. 해당 업무의 판단 기준
6. 진행 절차
7. 준비서류
8. 기한·비용에 영향을 주는 요소
9. 실제 사례 또는 명확히 표시된 가상 예시
10. 자주 발생하는 실수
11. 관련 질문
12. 관련 업무 내부링크
13. 상담 CTA

핵심 요약 직후에는 카드와 체크리스트를 연속으로 배치하지 말고 줄글 본문이 먼저 나오게 한다.

본문에서는 다음을 구체적으로 설명한다.

- 사용자가 왜 이 키워드를 검색하게 되었는지
- 첫 번째로 확인해야 할 사실
- 비슷해 보이는 다른 절차와의 차이
- 상황에 따라 결론이 달라지는 조건
- 직접 처리하기 비교적 단순한 경우
- 전문가 검토가 필요한 경우
- 준비서류가 부족할 때 시작하는 방법
- 절차를 미루거나 잘못 진행했을 때 생길 수 있는 문제
- 실제 상담에서 법무사가 먼저 확인하는 사항

“핵심 요약”, “핵심 결론”, “이런 상황인가요?”, “지금 할 일”, “혼자 처리 가능한 경우”를 각각 별도 카드로 반복하지 않는다. 핵심 요약은 1개만 두고 나머지는 본문과 필요한 섹션에 자연스럽게 통합한다.

6. 제목 작성 기준
━━━━━━━━━━━━━━━━━━━━

주 키워드는 title과 H1에서 자연스럽게 한 번만 사용한다.

다음처럼 키워드를 나열하지 않는다.

- 부산 법무사 부산 상속전문 법무사 부산 상속등기 추천
- 부산 법인전문 법무사 법인등기 법인설립 기업법무
- 부산 개인회생 법무사 추천 비용 상담 전문

다음처럼 검색 의도와 클릭 이유가 드러나게 작성한다.

- 부산 한정승인 법무사｜상속채무가 걱정될 때 3개월 안에 확인할 절차
- 부산 개인회생 법무사｜소득·채무·재산으로 보는 신청 가능성
- 부산 상속 법무사｜상속등기·상속포기·한정승인 중 무엇이 필요할까
- 부산 상속등기 법무사｜상속인 구성에 따라 달라지는 서류와 진행 순서
- 부산 법인등기 법무사｜임원·본점·사업목적 변경을 놓치지 않으려면
- 부산 법무사｜상속·부동산·법인등기에서 먼저 확인할 기준
- 부산 법인 임원변경등기｜대표이사·이사 임기와 과태료 확인사항
- 부산 건물멸실등기｜철거 후 건축물대장만 정리하면 끝일까

모든 페이지에 “절차·비용·서류 총정리”를 반복하지 않는다.

title은 다음 조합을 페이지별로 다양하게 사용한다.

- 지역 + 업무 + 긴급한 상황
- 지역 + 업무 + 판단 기준
- 지역 + 업무 + 자주 생기는 실수
- 지역 + 업무 + 기한
- 실제 상황 + 해결 절차
- 두 제도의 차이
- 준비서류 + 진행 순서

기존 title이 이미 검색 노출이나 클릭을 받고 있을 가능성이 있으면 무조건 변경하지 않는다. Search Advisor 또는 분석 데이터가 있으면 노출·클릭·CTR을 확인하고, 성과가 있는 제목은 핵심 구조를 유지한다.

━━━━━━━━━━━━━━━━━━━━
7. description·H1·메타데이터
━━━━━━━━━━━━━━━━━━━━

각 페이지에 고유한 메타정보를 작성한다.

- title 1개
- H1 1개
- description 1~2문장
- self canonical
- 고유 Open Graph title
- 고유 Open Graph description
- 페이지를 대표하는 고유 이미지
- 실제 내용에 맞는 alt

description은 제목을 그대로 복사하지 않고, 사용자가 페이지에서 얻을 수 있는 답을 요약한다.

예:

“상속재산보다 채무가 많거나 채무 규모를 알기 어려울 때 검토하는 한정승인 절차를 안내합니다. 신청기한, 상속재산 처분 여부, 준비서류와 이후 절차를 확인할 수 있습니다.”

동일한 description이나 공통 홍보 문구를 여러 페이지에 반복하지 않는다.

대표 이미지는 단순 로고나 동일한 홍보 배너를 전 페이지에서 재사용하지 말고 업무 유형을 구분할 수 있는 이미지 체계를 만든다.

━━━━━━━━━━━━━━━━━━━━
8. 콘텐츠 품질과 법률 정확성
━━━━━━━━━━━━━━━━━━━━

법률 내용을 임의로 추정하거나 오래된 일반론으로 작성하지 않는다.

페이지마다 다음을 확인한다.

- 적용 법률과 절차
- 법정기한
- 관할
- 준비서류
- 예외 상황
- 최근 변경 여부
- 법무사가 수행할 수 있는 업무 범위
- 세무·행정·소송 등 별도 확인이 필요한 영역

공식 법령, 법원, 등기 관련 공식 자료 등 신뢰할 수 있는 근거를 우선 사용한다.

실제 상담사례는 프로젝트에 존재하는 검증 가능한 사례만 익명화하여 사용한다. 존재하지 않는 사례를 실제 사례처럼 만들지 않는다.

실제 사례가 없을 때는 다음처럼 명시한다.

- “이해를 위한 가상 예시”
- “상황을 단순화한 예시”
- “실제 결과는 개별 사정에 따라 달라질 수 있습니다”

각 핵심 페이지에 다음 신뢰 요소를 적절히 표시한다.

- 작성 또는 검토: 안윤정 법무사
- 다옴법무사사무소
- 실제 검토일
- 주요 업무 범위
- 사안별 결과가 달라질 수 있다는 안내

법무사의 자격·경력·강의·상담 경험은 프로젝트에 실제 존재하는 사실만 활용하고 모든 페이지에서 똑같이 길게 반복하지 않는다.

AI로 생성한 일반적인 표현을 그대로 사용하지 말고, 기존 사이트의 실제 업무 방식·부산 지역성·사무소의 상담 기준·확인 서류를 반영하여 고유한 콘텐츠로 다듬는다.

━━━━━━━━━━━━━━━━━━━━
9. 지역 키워드 적용
━━━━━━━━━━━━━━━━━━━━

“부산”은 모든 문단에 반복하지 않는다.

다음 위치에서만 자연스럽게 사용한다.

- title
- H1
- 도입부
- 관할 또는 지역 설명
- 실제 부산 사례
- 상담 안내

부산 세부 지역 페이지는 지역명만 교체해 생성하지 않는다.

별도 지역 페이지는 다음 중 하나 이상이 있을 때만 허용한다.

- 지역과 직접 연결되는 업무 수요
- 실제 관할 또는 등기 절차 설명
- 해당 지역의 부동산·기업 유형
- 지역별 고유 상담 사례
- 해당 지역에서 사무소로 접근하거나 비대면 진행하는 방법

고유한 정보를 작성할 수 없는 “구·동+동일 업무” 조합은 상위 부산 허브의 본문과 관련 지역 목록에서 흡수한다.

━━━━━━━━━━━━━━━━━━━━
10. 중복과 키워드 잠식 해결
━━━━━━━━━━━━━━━━━━━━

페이지 생성 또는 수정 전에 다음을 비교한다.

- 주 키워드
- 검색 의도
- title
- H1
- description
- 첫 500자
- 소제목
- 준비서류
- 사례
- FAQ
- 최종 결론

검색 의도가 동일한 두 페이지가 있으면 하나의 대표 URL을 지정한다.

기존 URL을 유지해야 하므로 다음 순서로 처리한다.

1. 두 페이지를 서로 다른 고유 검색 의도로 재정의할 수 있는지 검토
2. 가능하면 각각의 본문·제목·사례·FAQ를 완전히 차별화
3. 불가능하면 대표 URL과 통합 후보 URL을 보고
4. redirect, canonical, noindex는 자동 적용하지 않고 승인 대기

페이지별로 하나의 primary keyword만 지정한다.

예:

- `/부산한정승인법무사` → 부산 한정승인 법무사
- `/상속채무확인` → 부모님 빚 상속 확인
- `/한정승인3개월경과` → 한정승인 기간 경과
- `/상속재산처분후한정승인` → 상속재산 처분 후 한정승인

각 URL이 서로 다른 질문에 답하도록 만든다.

━━━━━━━━━━━━━━━━━━━━
11. 내부링크 구조
━━━━━━━━━━━━━━━━━━━━

다음 구조를 만든다.

부산 법무사 메인 허브
→ 상속·부동산·법인·회생파산 업무 허브
→ 핵심 업무 페이지
→ 구체적인 상황 페이지
→ 실제 사례
→ 상담하기

모든 핵심 페이지는 다음 링크를 갖는다.

- 상위 허브 1개
- 관련 업무 3개 이상
- 구체적인 상황 페이지 2개 이상
- 실제 사례 또는 FAQ 페이지
- 상담 페이지

내부링크의 앵커 텍스트는 “자세히 보기”만 반복하지 않는다.

예:

- 한정승인 신청기한 확인
- 해외 상속인이 있는 상속등기
- 대표이사 임기만료 변경등기
- 개인회생 준비서류 확인

사이트 전체 푸터에 수백 개의 키워드 링크를 나열하지 않는다. 중요한 페이지는 본문, 허브, 메뉴, 관련 콘텐츠 영역에서 자연스럽게 연결한다.

━━━━━━━━━━━━━━━━━━━━
12. 사용자 경험과 상담 전환
━━━━━━━━━━━━━━━━━━━━

페이지 상단부터 상담 버튼을 반복하지 않는다.

권장 배치:

- 상단: 핵심 답변과 본문
- 본문 중간: 작은 상담 안내 1회
- 본문 하단: 주요 상담 CTA 1회
- 전역 플로팅 상담 버튼 유지

CTA는 업무별 상황에 맞게 작성한다.

한정승인:
“사망일, 상속인 구성, 확인된 재산과 채무를 남겨주시면 먼저 확인할 절차를 정리할 수 있습니다.”

개인회생:
“월 소득, 채무 규모, 재산 현황을 기준으로 신청 가능성을 확인해보세요.”

상속등기:
“부동산과 상속인 구성을 알려주시면 필요한 서류와 진행 방식을 확인할 수 있습니다.”

법인등기:
“등기사항증명서와 정관을 기준으로 누락된 변경등기가 있는지 확인해보세요.”

부산 법무사:
“업무명을 정확히 모르셔도 현재 상황과 준비된 자료만 남겨주세요.”

상담 버튼을 누르면 현재 페이지의 다음 정보가 상담 폼에 자동 전달되게 한다.

- 업무 분야
- 세부 상황
- 지역
- 페이지 제목
- 페이지 URL

과장된 긴급성, 허위 후기, “무조건 가능”, “최저 비용”, “즉시 해결” 같은 표현은 사용하지 않는다.

━━━━━━━━━━━━━━━━━━━━
13. 기술 SEO
━━━━━━━━━━━━━━━━━━━━

다음을 검사하고 필요한 부분만 수정한다.

- 핵심 본문이 초기 HTML에 포함되는지
- JavaScript 실행 전에도 title, H1, 본문, 링크가 보이는지
- HTTP 200인지
- robots 수집 허용 여부
- noindex 여부
- self canonical
- sitemap 포함
- sitemap URL과 canonical 일치
- 중복 title·description·H1
- 404·redirect URL이 sitemap에 없는지
- 페이지당 H1 1개
- 의미 있는 heading 계층
- breadcrumb
- WebPage 또는 Article 구조화 데이터
- Organization·LocalBusiness 정보의 일관성
- 모바일 가독성
- 과도한 HTML 크기와 공통 콘텐츠 반복
- LCP·INP·CLS
- Cloudflare가 Yeti에 정상 응답하는지

FAQ는 사용자가 실제로 궁금해하는 질문을 답하는 본문 요소로 활용하되, 검색결과 장식을 위한 반복적·기계적인 FAQ 생성은 하지 않는다.

IndexNow는 모든 URL을 반복 전송하지 말고 새로 생성하거나 실제 내용이 변경된 URL만 전송하도록 한다.

━━━━━━━━━━━━━━━━━━━━
14. 품질 검수 기준
━━━━━━━━━━━━━━━━━━━━

신규 또는 개편 페이지는 다음 기준을 모두 충족할 때만 배포한다.

- 다른 페이지와 검색 의도가 독립적
- 주 키워드가 다른 URL과 충돌하지 않음
- 고유한 title·H1·description
- 최소 권장 수준의 실질적인 줄글 본문
- 다른 페이지에서 복사하지 않은 도입과 결론
- 고유한 판단 기준 또는 절차
- 실제 사례 또는 명확히 표시된 예시
- 관련 법률 내용 검토
- 상위·하위 내부링크 존재
- self canonical
- sitemap 포함
- 모바일 UI 정상
- 상담 흐름 연결
- 빌드 오류 없음

키워드 밀도나 반복 횟수를 목표로 삼지 않는다.

다음 방식은 금지한다.

- 주 키워드 10회·15회 등 횟수 맞추기
- 지역명 반복
- 동의어 나열
- 동일한 템플릿 대량 복제
- 같은 FAQ의 반복
- 표현만 바꾼 AI 문장
- 존재하지 않는 사례
- 근거 없는 비용·기간·성공 가능성 단정
- 검색 노출만을 위한 얇은 페이지

━━━━━━━━━━━━━━━━━━━━
15. 단계적 배포
━━━━━━━━━━━━━━━━━━━━

한 번에 수십·수백 페이지를 대량 배포하지 않는다.

1차:
가장 중요한 대표 페이지 5개 개선

- 부산 법무사
- 부산 한정승인 법무사
- 부산 개인회생 법무사
- 부산 상속 법무사
- 부산 법인등기 법무사

2차:
대표 페이지와 연결되는 고전환 상황 페이지 10~15개 개선 또는 생성

3차:
검색 의도가 독립적인 세부 업무·지역 페이지 확장

각 단계마다 다음을 확인한다.

- 수집 여부
- 색인 여부
- 노출 검색어
- 페이지별 노출 수
- 클릭 수
- CTR
- 체류와 상담 시작 이벤트
- 키워드 잠식 여부

데이터가 없으면 프로젝트에 측정용 페이지·키워드 매핑표를 생성하고, 수동으로 Search Advisor 데이터를 기록할 수 있는 형식을 제공한다.

━━━━━━━━━━━━━━━━━━━━
16. 완료 보고
━━━━━━━━━━━━━━━━━━━━

작업 후 다음을 보고해줘.

1. 전체 페이지 SEO 진단표
2. KEEP·IMPROVE·REPOSITION·MERGE-CANDIDATE·CREATE 분류
3. 핵심 키워드별 대표 URL
4. 키워드 잠식이 발생하는 URL 목록
5. 수정한 페이지의 변경 전·후 title 비교
6. 수정한 페이지의 변경 전·후 검색 의도
7. 신규 생성 페이지와 생성 이유
